# Revisão de Segurança e LGPD (Fase 5)

Revisão feita em 2026-11-23 sobre o código da Fase 4, usando como roteiro o
[OWASP API Security Top 10 (2023)](https://owasp.org/API-Security/editions/2023/en/0x11-t10/)
e os requisitos RNF03–RNF10.

## 1. Falhas encontradas e corrigidas nesta fase

## 2. Checklist OWASP API Top 10

| Risco                                | Situação   | Como é tratado                                                                                                                                                                                                                                                                                                      |
| ------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API1 — Autorização por objeto (BOLA) | ✅         | O portal filtra sempre por `clienteId` do token, e OS de outro cliente responde 404 (ADR-07). Técnico só altera as próprias etapas (RN16), e ocorrências só pelo responsável ou pela gestão. Testes em `portal`, `fluxo-ordem` e `operacao`.                                                                        |
| API2 — Autenticação                  | ✅         | bcrypt (custo 12); JWT HS256 com algoritmo, emissor e público fixados (`alg: none` é rejeitado); mensagem única para credencial inválida; comparação em tempo constante mesmo para e-mail inexistente; limite de tentativas falhas por IP; usuário recarregado a cada requisição; revogação na troca de senha (S2). |
| API3 — Autorização por propriedade   | ✅         | Schemas `strict` rejeitam campos extras (mass assignment). Respostas usam projeções explícitas (`senhaHash` nunca sai). O TECNICO recebe cliente com CPF mascarado (ADR-16), e o portal usa lista branca de campos.                                                                                                 |
| API4 — Consumo de recursos           | ⚠️ parcial | Corpo JSON de até 1 MB, upload de até 10 MB / 1 arquivo, paginação máxima de 100, timeouts de transação finitos. **Não há** limite global de requisições por cliente (só no login).                                                                                                                                 |
| API5 — Autorização por função        | ✅         | `authorize(...)` em todas as rotas. O teste de contrato (`openapi.test.ts`) confere, para os 5 perfis e as 42 operações, que o 403 ocorre exatamente para quem não está documentado.                                                                                                                                |
| API6 — Fluxos de negócio sensíveis   | ✅         | Máquinas de estado, justificativas obrigatórias e decisões humanas (aprovação de documentos, entrega) restritas à gestão.                                                                                                                                                                                           |
| API7 — SSRF                          | ✅ n/a     | A API não faz requisições a URLs fornecidas pelo usuário.                                                                                                                                                                                                                                                           |
| API8 — Configuração                  | ✅         | Helmet; CORS com lista de origens; `x-powered-by` desativado; `.env` validado com Zod (segredo do JWT ≥ 32 caracteres); erros 500 genéricos; PostgreSQL publicado só em `127.0.0.1`.                                                                                                                                |
| API9 — Inventário                    | ✅         | API versionada (`/api/v1`); OpenAPI gerado dos schemas de validação e testado contra as rotas reais.                                                                                                                                                                                                                |
| API10 — Consumo inseguro de APIs     | ✅ n/a     | Sem integrações externas.                                                                                                                                                                                                                                                                                           |

| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 4. Riscos aceitos e recomendações

| Item                                  | Decisão                                                                                                                                   |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `minimatch` (moderada) no `nodemon`   | **Aceito.** Ferramenta só de desenvolvimento, que lê padrões do nosso `nodemon.json`. Nenhuma entrada externa.                            |
| Rate limit em memória e só no login   | Aceito para o escopo acadêmico. Em produção com várias instâncias: store compartilhado (Redis) e limite também por conta.                 |
| Sem bloqueio de conta após falhas     | O rate limit por IP mitiga. Recomendação: bloqueio temporário por conta.                                                                  |
| Upload em memória (10 MB)             | Muitos uploads simultâneos consomem RAM. Recomendação: proxy reverso com limite de conexões, ou upload em streaming para storage externo. |
| Sem refresh token (ADR-11)            | A validade de 8 h e a revogação na troca de senha (S2) reduzem o risco.                                                                   |
| HTTPS                                 | Responsabilidade do proxy reverso em produção. `trust proxy` já está configurado para `NODE_ENV=production`.                              |
| Anonimização LGPD a pedido do titular | Evolução futura. Hoje a inativação é lógica, e o histórico das OS é preservado por obrigação de guarda.                                   |
